# 材料管理接口说明

本文档对应第三阶段 3.4 和 3.11 任务，说明材料上传、下载、预览、删除、材料预处理联调和材料类型维护接口。除下载、预览文件响应外，业务接口均返回统一响应结构。

## 一、档案材料接口

### 1. 查询材料列表

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `GET` |
| 请求路径 | `/api/materials` |

查询参数：

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| recordId | 否 | 考籍档案 ID。 |
| materialType | 否 | 材料类型编码。 |

### 2. 上传材料

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `POST` |
| 请求路径 | `/api/materials/upload` |
| Content-Type | `multipart/form-data` |

表单字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| recordId | 是 | 考籍档案 ID。 |
| materialType | 是 | 已启用的材料类型编码。 |
| file | 是 | 上传文件。当前支持 `jpg`、`jpeg`、`png`、`pdf`。 |

上传成功后，系统会将文件保存到后端本地材料目录，并写入 `record_material` 记录。默认审核状态为 `PENDING`。

### 3. 下载材料

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `GET` |
| 请求路径 | `/api/materials/{id}/download` |

路径参数：

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| id | 是 | 材料 ID。 |

该接口返回文件流，响应头使用 `Content-Disposition: attachment`。

### 4. 预览材料

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `GET` |
| 请求路径 | `/api/materials/{id}/preview` |

该接口返回文件流，响应头使用 `Content-Disposition: inline`。前端可直接用浏览器预览图片和 PDF。

### 5. 删除材料

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `DELETE` |
| 请求路径 | `/api/materials/{id}` |

删除动作只处理单条材料记录及其对应的单个本地文件，不提供批量删除接口。

## 二、材料智能预处理接口

### 1. 发起材料预处理

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `POST` |
| 请求路径 | `/api/ai/material-preprocess` |

请求体示例：

```json
{
  "businessId": 2026052701,
  "scene": "MATERIAL_AUDIT",
  "fileUrl": "https://example.com/mock/idcard-sample.jpg",
  "fileName": "idcard-sample.jpg",
  "contentType": "image/jpeg",
  "fileSizeKb": 768,
  "materialTypeHint": "身份证"
}
```

响应数据说明：

| 字段 | 说明 |
| --- | --- |
| `format_validation` | 材料格式校验结果，包含是否通过、文件后缀、MIME 类型、最大允许大小和问题列表。 |
| `clarity` | 图片清晰度检测结果，非图片材料返回 `NOT_IMAGE` 并跳过清晰度检测。 |
| `category_code` / `category_name` | 基础材料分类结果。 |
| `confidence` | 基础分类置信度。 |
| `candidates` | 候选材料类别列表。 |
| `suggested_action` | 系统建议动作，取值为 `ACCEPT`、`REVIEW`、`REJECT`。 |
| `need_manual_review` | 是否建议人工复核。 |

前端材料审核页会先逐条调用该接口展示格式、清晰度和基础分类结果，再调用申请材料智能核验接口展示缺失材料和异常材料提醒。

## 三、材料类型维护接口

### 1. 查询材料类型

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `GET` |
| 请求路径 | `/api/material-types` |

查询参数：

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| status | 否 | `ENABLED` 或 `DISABLED`。 |

### 2. 新增材料类型

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `POST` |
| 请求路径 | `/api/material-types` |

请求体示例：

```json
{
  "typeCode": "ID_CARD",
  "typeName": "身份证材料",
  "description": "用于核验考生身份信息。",
  "sortOrder": 10,
  "status": "ENABLED"
}
```

### 3. 修改材料类型

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `PUT` |
| 请求路径 | `/api/material-types/{id}` |

材料类型编码新增后保持稳定，修改接口只维护名称、说明、排序和状态。

### 4. 删除材料类型

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `DELETE` |
| 请求路径 | `/api/material-types/{id}` |

当前接口只删除单个材料类型。已经被历史材料使用的类型，建议优先禁用而不是删除。
