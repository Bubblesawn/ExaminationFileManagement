# 认证接口说明

## 一、接口概述

第二阶段 2.2 已实现登录、退出、Token 生成、Token 校验和登录失败记录。除登录接口、健康检查和接口文档地址外，后端 `/api/**` 接口默认需要携带认证请求头。

认证请求头格式：

```text
Authorization: Bearer <token>
```

## 二、接口列表

### 1. 登录

- 请求地址：`POST /api/auth/login`
- 是否需要 Token：否
- 请求体：

```json
{
  "username": "admin",
  "password": "admin123"
}
```

- 成功响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "登录凭证",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "user": {
      "id": 1,
      "username": "admin",
      "realName": "系统管理员",
      "avatar": null
    }
  }
}
```

- 登录失败处理：
  - 账号不存在或密码错误：返回 `401`，提示“账号或密码错误”。
  - 账号禁用：返回 `403`，提示“账号已禁用，请联系管理员”。
  - 登录成功和失败都会写入 `sys_login_log`。

### 2. 退出

- 请求地址：`POST /api/auth/logout`
- 是否需要 Token：是
- 成功响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": null
}
```

退出后当前 Token 会进入服务内存失效列表，再次访问受保护接口会返回 `401`。

### 3. 获取当前登录用户

- 请求地址：`GET /api/auth/me`
- 是否需要 Token：是
- 成功响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 1,
    "username": "admin",
    "realName": "系统管理员"
  }
}
```

## 四、实现说明

- Token 使用 HMAC-SHA256 签名，配置项位于 `application.yml` 的 `auth.token` 节点。
- 当前密码校验兼容 `{noop}` 明文占位和 `{sha256}` 哈希格式。
- `AuthInterceptor` 负责统一校验 `/api/**` 受保护接口，并把用户信息写入 `AuthContextHolder`。
