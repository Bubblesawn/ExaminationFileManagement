# 日志管理接口说明

第二阶段 2.6 已实现登录日志和操作日志的记录、分页查询和详情查询接口。除登录接口外，日志查询接口需要携带 `Authorization: Bearer <token>` 请求头。

## 一、登录日志

### 1. 分页查询登录日志

- 请求方式：`GET`
- 请求地址：`/api/system/logs/login/page`
- 查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| pageNo | 否 | 当前页码，默认 `1` |
| pageSize | 否 | 每页条数，默认 `10` |
| username | 否 | 登录账号关键字 |
| loginStatus | 否 | 登录状态：`SUCCESS` 成功，`FAIL` 失败 |

### 2. 查询登录日志详情

- 请求方式：`GET`
- 请求地址：`/api/system/logs/login/{id}`
- 路径参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| id | 是 | 登录日志 ID |

## 二、操作日志

### 1. 自动记录规则

系统会自动记录已认证的 `/api/**` 内部接口操作日志，当前排除以下地址：

- `/api/auth/login`：登录成功和失败由登录日志单独记录。
- `/api/health`：健康检查不记录。
- `/api/system/logs/**`：日志查询接口不记录，避免日志页面刷新产生大量审计噪音。
- 接口文档和静态资源地址。

操作日志记录字段包括模块名称、操作类型、请求方式、请求地址、查询参数、响应摘要、操作状态、错误信息、操作人、客户端 IP、操作时间和耗时。

### 2. 分页查询操作日志

- 请求方式：`GET`
- 请求地址：`/api/system/logs/operation/page`
- 查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| pageNo | 否 | 当前页码，默认 `1` |
| pageSize | 否 | 每页条数，默认 `10` |
| moduleName | 否 | 模块名称关键字 |
| operatorName | 否 | 操作人姓名关键字 |
| operationStatus | 否 | 操作状态：`SUCCESS` 成功，`FAIL` 失败 |

### 3. 查询操作日志详情

- 请求方式：`GET`
- 请求地址：`/api/system/logs/operation/{id}`
- 路径参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| id | 是 | 操作日志 ID |

## 三、统一响应格式

接口返回格式与项目其他后端接口保持一致：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```
