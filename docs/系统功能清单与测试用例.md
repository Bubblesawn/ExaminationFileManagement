# 系统功能清单与测试用例

## 一、文档说明

本文档对应《实施计划》第六阶段 6.1“整理系统功能清单和测试用例”，用于综合测试、联调测试和最终验收前的用例执行依据。

测试范围覆盖登录认证、系统管理、考籍核心业务、业务流程、智能辅助、日志审计和三端联调主流程。测试执行时应优先使用 `sql/test-data.sql` 初始化的演示账号和基础数据，避免批量删除测试数据。

## 二、测试账号

| 账号 | 密码 | 角色 | 主要验证范围 |
| --- | --- | --- | --- |
| admin | admin123 | 超级管理员 | 全量功能、系统管理、权限配置、日志查询 |
| record_manager | record123 | 考籍管理员 | 考生、考籍档案、材料管理、业务申请提交 |
| auditor | audit123 | 业务审核员 | 免考、课程顶替、转考、毕业等审核流程 |

## 三、系统功能清单

| 模块 | 功能项 | 后端接口范围 | 前端页面或组件 | 验收要点 |
| --- | --- | --- | --- | --- |
| 登录认证 | 登录、退出、Token 校验、未登录拦截 | `/api/auth/login`、`/api/auth/logout`、`/api/auth/me` | 登录页、主布局路由守卫 | 正确登录；错误账号提示；退出后 Token 失效；未登录不能访问内部接口和页面 |
| 权限控制 | 角色菜单权限、接口权限拦截、工作台权限聚合 | `/api/system/roles/**`、`/api/system/menus/**`、`/api/dashboard/stats` | 系统管理、侧栏菜单、工作台 | 不同角色看到对应菜单；无权限接口返回 403；统计数据不泄露无权限模块 |
| 用户管理 | 用户分页、新增、编辑、启用、禁用、重置密码 | `/api/system/users/**` | 用户管理页 | 用户信息可维护；账号唯一校验；禁止禁用或删除当前登录用户 |
| 角色管理 | 角色分页、新增、编辑、删除、分配菜单 | `/api/system/roles/**` | 角色管理页 | 角色编码唯一；已分配用户的角色不能删除；授权后重新登录权限生效 |
| 菜单管理 | 菜单列表、菜单树、新增、编辑、删除、排序 | `/api/system/menus/**` | 菜单管理页 | 菜单树结构正确；权限标识唯一；存在子菜单时不能直接删除 |
| 日志管理 | 登录日志、操作日志分页与详情 | `/api/system/logs/**` | 日志管理页 | 登录成功、失败和关键操作可追溯 |
| 考生管理 | 考生分页、新增、编辑、详情、导入预览 | `/api/candidates/**` | 考生信息管理页 | 身份证号、准考证号唯一；导入预览能返回校验结果 |
| 考籍档案 | 档案创建、编辑、状态更新、归档、变更记录 | `/api/records/**` | 考籍档案管理页、变更记录页 | 考籍号唯一；状态变更写入记录；归档不能重复执行 |
| 材料管理 | 材料类型维护、材料上传、列表、预览、下载、删除 | `/api/material-types/**`、`/api/materials/**` | 材料上传预览组件、材料审核页 | 支持图片和 PDF；材料归属档案校验；格式错误有明确提示 |
| 免考申请 | 提交、修改、撤回、审核通过、驳回、流程记录 | `/api/exemptions/**` | 免考申请页 | 只有已提交状态允许修改、撤回和审核；重复申请受限 |
| 课程顶替 | 规则维护、申请提交、修改、撤回、审核、流程记录 | `/api/course-replacements/**` | 课程顶替页 | 规则有效期、专业、层次校验正确；流程记录完整 |
| 考籍转入转出 | 转入/转出申请、修改、撤回、审核、流程记录 | `/api/transfers/**` | 考籍转入转出页 | 转入必须填写来源省份；转出必须填写目标省份；转出审核通过联动档案状态 |
| 毕业申请 | 资格校验、提交、修改、撤回、审核、结果查询 | `/api/graduations/**` | 毕业申请页 | 资格不通过时阻断提交；审核通过联动档案状态为已毕业 |
| 流程记录 | 按业务类型、业务 ID 和档案 ID 查询流程记录 | `/api/workflow-records` | 各业务详情时间线 | 查询条件校验正确；各业务提交、修改、审核动作可追溯 |
| 智能辅助 | 图像分类、目标检测、图像分割、材料预处理、材料智能核验、问答、ASR、TTS | `/api/ai/**` | 智能辅助页、识别结果组件、材料智能核验组件 | 后端统一携带算法服务密钥；算法异常转换为统一响应；结果可展示和人工复核 |
| 健康检查 | 后端服务可用性检查 | `/api/health` | 无 | 不需要登录即可访问，返回服务正常状态 |

### 6. 异常与边界

| TC-ERR-005 | 算法服务不可用 | 停止算法服务或配置错误地址 | 调用 `/api/ai/**` 接口 | 后端返回统一错误，不暴露内部堆栈 |

## 五、执行顺序建议

1. 导入 `sql/init.sql` 和 `sql/test-data.sql`。
2. 启动后端、前端和算法服务。
3. 先执行登录认证、权限控制和健康检查用例。
4. 再执行考生、档案、材料等基础数据用例。
5. 按免考、课程顶替、转考、毕业顺序执行流程用例。
6. 最后执行智能辅助、异常输入和三端联调用例。

## 六、通过标准

- P0/P1 阻断问题全部修复并完成回归。
- 系统主流程可以使用演示账号连续走通。
- 后端接口响应结构保持 `code`、`message`、`data` 统一格式。
- 前端页面能正确展示成功、失败和无权限提示。
- 智能辅助接口在算法服务可用时正常返回，在算法服务不可用时有明确错误。
- 测试过程中产生的临时数据如需清理，应按项目约定先确认范围并申请后再执行。
