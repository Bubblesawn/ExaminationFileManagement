# 考籍转入转出接口说明

## 一、接口范围

本文档对应第四阶段 4.4 任务，覆盖考籍转入、考籍转出申请提交、修改、撤回、审核通过、审核驳回、分页查询、详情查询和流程记录查询接口。

## 二、接口列表

| 功能 | 请求方式 | 地址 |
| --- | --- | --- |
| 分页查询转考申请 | GET | `/api/transfers/page` |
| 查询转考申请详情 | GET | `/api/transfers/{id}` |
| 提交转考申请 | POST | `/api/transfers` |
| 修改转考申请 | PUT | `/api/transfers/{id}` |
| 撤回转考申请 | PUT | `/api/transfers/{id}/withdraw` |
| 审核通过转考申请 | PUT | `/api/transfers/{id}/approve` |
| 驳回转考申请 | PUT | `/api/transfers/{id}/reject` |
| 查询转考流程记录 | GET | `/api/transfers/{id}/flow-records` |

## 三、状态约定

转考类型 `transferType` 支持以下值：

| 值 | 说明 |
| --- | --- |
| `TRANSFER_IN` | 考籍转入 |
| `TRANSFER_OUT` | 考籍转出 |

申请状态 `applicationStatus` 支持以下值：

| 值 | 说明 |
| --- | --- |
| `SUBMITTED` | 已提交 |
| `APPROVED` | 审核通过 |
| `REJECTED` | 审核驳回 |
| `WITHDRAWN` | 已撤回 |

## 四、请求示例

### 1. 提交考籍转入申请

```json
{
  "recordId": 1,
  "transferType": "TRANSFER_IN",
  "sourceProvince": "湖南省",
  "sourceSchool": "湖南省自考办",
  "sourceRecordNo": "HN2024010101",
  "transferReason": "考生工作地变更，申请转入本省继续考试",
  "materialIds": [3, 4],
  "remark": "材料已由考生确认"
}
```

### 2. 提交考籍转出申请

```json
{
  "recordId": 2,
  "transferType": "TRANSFER_OUT",
  "targetProvince": "浙江省",
  "targetSchool": "浙江省自考办",
  "transferReason": "考生长期居住地变更，申请转出",
  "materialIds": [8],
  "remark": "等待接收地复核"
}
```

### 3. 审核转考申请

```json
{
  "auditOpinion": "材料齐全，符合转考办理要求"
}
```

### 4. 查询转考申请

```text
GET /api/transfers/page?pageNo=1&pageSize=10&transferType=TRANSFER_OUT&applicationStatus=SUBMITTED
```

## 五、业务说明

- 提交申请时会校验考籍档案是否存在、材料是否属于当前档案。
- `TRANSFER_IN` 必须填写 `sourceProvince`，`TRANSFER_OUT` 必须填写 `targetProvince`。
- 同一档案同一转考类型不允许同时存在已提交或已通过的重复申请。
- 只有 `SUBMITTED` 状态允许修改、撤回和审核。
- 审核通过考籍转出申请后，系统会同步将档案状态更新为 `TRANSFERRED_OUT`，并写入档案状态记录和档案变更记录。
- 提交、修改、撤回、审核通过、审核驳回都会写入 `audit_record`，用于流程时间线展示。
