# 算法服务鉴权说明

## 一、方案概述

第二阶段 2.12 已补充算法服务访问控制方案。系统采用“前端用户 Token + 后端服务间密钥”的双层边界：

- 前端只调用 Spring Boot 后端接口，并继续使用 `Authorization: Bearer <token>` 完成用户登录认证。
- 后端校验用户 Token 和业务权限后，再代表用户调用 FastAPI 算法服务。
- 算法服务不接收前端用户 Token，不直接暴露给前端页面，仅校验后端携带的内部 API Key。

## 二、认证方式

后端调用算法服务时，在每个 `/api/**` 算法接口请求中增加以下请求头：

```text
X-Internal-Api-Key: <algorithm-service-api-key>
```

本地开发默认密钥为：

```text
examination-algorithm-local-key
```

生产环境必须使用更强的随机密钥，并通过配置或环境变量覆盖默认值。

## 三、配置位置

### 1. 后端 Spring Boot

配置项位于 `backend/src/main/resources/application.yml`：

```yaml
algorithm:
  service:
    base-url: http://localhost:9000/api
    api-key: examination-algorithm-local-key
```

`AiAssistServiceImpl` 统一封装后端到算法服务的调用，并在请求头中写入 `X-Internal-Api-Key`。

### 2. 算法服务 FastAPI

算法服务默认读取环境变量：

```text
ALGORITHM_SERVICE_API_KEY
```

未设置环境变量时，使用本地开发默认密钥。`algorithm-service/app/api/security.py` 负责校验内部 API Key，`algorithm-service/app/api/routes.py` 将该校验作为 `/api/**` 业务接口的统一依赖。

## 四、访问控制规则

| 接口范围 | 是否需要认证 | 认证方式 |
| --- | --- | --- |
| 后端 `/api/auth/login` | 否 | 用户名和密码 |
| 后端其他 `/api/**` 接口 | 是 | `Authorization: Bearer <token>` |
| 算法服务 `/health` | 否 | 健康检查不校验 |
| 算法服务 `/api/**` 接口 | 是 | `X-Internal-Api-Key` |

## 五、异常响应

当算法服务请求未携带内部 API Key 或密钥不匹配时，返回 HTTP `401`：

```json
{
  "detail": "算法服务认证失败"
}
```

后端收到算法服务认证失败或网络异常后，由智能辅助服务统一记录调用日志，并向业务层抛出算法服务调用失败异常。

## 六、安全要求

- 算法服务端口仅允许后端服务器或内网网段访问，不能直接开放给公网或前端。
- 内部 API Key 不写入前端代码，不放入接口文档示例以外的公开材料。
- 生产环境密钥需要定期轮换，轮换时先更新算法服务环境变量，再更新后端配置并重启服务。
- 日志中禁止输出完整内部 API Key，只记录接口路径、业务 ID、场景、耗时和错误原因。
