## 五、重点问题清单

### 1. 前端缺少自动化页面测试用例

问题等级：中

现象说明：

当前前端项目未配置 Vitest、Cypress 或 Playwright 等自动化测试脚本，`package.json` 仅提供开发、构建和预览命令。

影响范围：

- 页面表单校验、路由守卫、权限菜单和异常提示主要依赖人工回归。
- 后续页面字段调整时，容易遗漏列表查询、详情弹窗和流程操作按钮的回归验证。

建议修复方向：

1. 补充组件级测试，优先覆盖登录表单、公共请求异常处理和材料上传前校验。
2. 补充端到端冒烟测试，覆盖登录、进入工作台、查询考籍、提交申请和查看智能辅助结果。
3. 将前端构建和端到端冒烟测试纳入交付前固定检查命令。

### 2. 需要补充真实浏览器执行记录

问题等级：中

现象说明：

当前已完成页面代码检查和用例清单整理，但尚未在完整联调环境中逐页执行真实浏览器操作。

影响范围：

- 页面加载状态、接口实际响应字段、权限菜单渲染、弹窗层级和移动端布局仍可能暴露问题。
- 文件上传、语音录制、TTS 播放等浏览器能力依赖真实环境验证。

建议修复方向：

1. 启动后端、前端和算法服务后，按第四章逐条执行浏览器自测。
2. 对失败项记录页面、账号、操作步骤、实际结果、期望结果和截图。
3. 将确认失败项纳入 6.6 修复与回归范围。

### 3. 删除类操作需限制测试数据范围

问题等级：低

现象说明：

系统管理、菜单管理和材料管理页面包含删除操作。根据项目协作约定，禁止批量删除文件或数据，删除前需要确认范围。

影响范围：

- 若直接删除演示基础数据，可能影响后续联调、演示和验收。

建议修复方向：

1. 删除测试仅使用临时新增的测试数据。
2. 删除前记录数据 ID 和业务含义，避免误删演示数据。
3. 不执行批量删除；确需清理历史测试数据时先向用户申请。

## 七、回归验证建议

1. 每次前端改动后先执行 `cd frontend && npm run build`。
2. 启动后端、前端和算法服务后，使用 `admin` 执行全量页面冒烟测试。
3. 使用 `record_manager` 验证考籍、材料、申请提交和无系统管理权限场景。
4. 使用 `auditor` 验证审核入口、流程记录和无系统配置权限场景。
5. 对材料上传、语音识别和语音播报保留截图或录屏作为 6.5 联调输入。
6. 所有失败项登记为明确问题，包含复现步骤、实际结果、期望结果、影响范围和建议修复方向。
