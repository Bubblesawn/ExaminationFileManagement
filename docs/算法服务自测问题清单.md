## 三、已通过检查项

1. `app.main` 已创建 FastAPI 应用，并将算法接口统一挂载到 `/api`。
2. `/health` 可用于后端和部署平台探活，返回 `status` 与 `service` 字段。
3. `/api/image-classify` 已提供材料类别识别接口，返回统一算法响应。
4. `/api/material-preprocess` 已提供格式校验、清晰度检测和分类候选结果。
5. `/api/application-material-audit` 已提供申请材料缺失、异常和整体建议动作结果。
6. `/api/object-detect` 已提供材料关键信息区域检测结果。
7. `/api/image-segment` 已提供材料图像分割区域、轮廓和掩码地址结果。
8. `/api/chat` 已提供考籍办理问答结果、参考依据和追问建议。
9. `/api/asr` 已提供语音识别文本、片段和置信度结果。
10. `/api/tts` 已提供播报音频地址、格式、时长和采样率结果。
11. 请求模型对必填字段、非负文件大小、置信度范围、边界框尺寸和枚举值设置了基础校验。
12. 算法服务入口、路由和模型已包含 Doxygen 风格注释，便于后续维护。

## 五、重点问题清单

### 1. 算法服务缺少自动化接口测试

问题等级：中

现象说明：

当前 `algorithm-service` 未配置 pytest、FastAPI TestClient 或接口自动化测试脚本，算法接口自测主要依赖代码审查和人工 HTTP 调用。

影响范围：

- 鉴权、422 参数校验、统一响应结构和异常输入无法自动回归。
- 后续切换真实模型或调整模拟算法逻辑时，容易破坏既有前后端联调契约。

建议修复方向：

1. 在 `algorithm-service/tests` 下补充 pytest 用例。
2. 使用 FastAPI TestClient 覆盖健康检查、鉴权失败、正常调用和异常输入。
3. 对全部业务接口增加顶层响应结构断言。
4. 将算法服务测试纳入交付前固定检查命令。

### 2. 需要补充真实 HTTP 调用记录

问题等级：中

现象说明：

当前已完成接口范围和模型约束检查，但尚未在启动后的算法服务上逐项执行 HTTP 请求。

影响范围：

- 环境变量、内部 API Key、端口占用、依赖安装和服务启动参数等运行时问题仍可能暴露。
- 后端调用算法服务时需要依赖真实 HTTP 可达性和请求头一致性。

建议修复方向：

1. 启动算法服务后按第四章用例逐条执行 curl、Postman 或 pytest 调用。
2. 保存关键请求、响应和失败截图，作为 6.5 三端联调输入。
3. 对失败项记录为明确问题，并在 6.6 修复后回归关闭。

### 3. 空字符串和文本长度边界需要明确业务策略

问题等级：低

现象说明：

Pydantic 模型已校验必填字段存在，但 `file_url`、`content`、`audio_url` 等字符串字段仍需要在业务层明确空字符串、纯空格和超长文本的处理策略。

影响范围：

- 前端可能传入空字符串导致算法模拟结果不符合业务预期。
- 智能问答和 TTS 文本过长时，响应策略不明确会影响交互体验。

建议修复方向：

1. 对关键字符串字段增加最小长度、最大长度或业务层清洗校验。
2. 对超长文本明确截断、拒绝或分段处理策略。
3. 将策略同步到接口说明文档和前端表单校验。

## 六、待补测接口清单

| 模块 | 待补测重点 | 建议执行方式 |
| --- | --- | --- |
| 健康检查 | `/health` 无鉴权探活 | curl 或浏览器 |
| 接口鉴权 | 缺少、错误、正确 API Key 三种场景 | curl 或 Postman |
| 图像能力 | 分类、检测、分割的正常响应和字段范围 | curl 或 pytest |
| 材料预处理 | 图片、PDF、不支持格式、超大文件 | curl 或 pytest |

| 智能问答 | 常见问题、空问题、未知问题 | curl 或 pytest |
| ASR/TTS | 音频地址、缺少字段、文本播报 | curl 或 pytest |
| 结果格式 | 顶层结构、枚举值、置信度、坐标范围 | pytest 断言 |

## 七、回归验证建议

1. 每次算法服务改动后执行依赖安装检查和 Python 语法编译检查。
2. 启动服务后先验证 `/health`，再验证鉴权失败和鉴权成功场景。
3. 使用统一样例请求覆盖所有 `/api/**` 算法接口。
4. 对异常输入重点验证 422 响应和业务可控错误，不允许暴露内部堆栈。
5. 与后端联调前确认内部 API Key、算法服务地址和响应结构一致。
6. 所有失败项登记为明确问题，包含请求体、响应体、实际结果、期望结果和建议修复方向。
