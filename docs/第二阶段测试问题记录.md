## 三、待整改问题

### 1. 未登录访问 Token 校验接口返回 500

问题等级：高

复现步骤：

1. 不携带 `Authorization` 请求头。
2. 请求后端接口：

```http
GET http://127.0.0.1:8088/api/auth/me
```

实际结果：

接口返回业务异常，内容包含：

```json
{
  "code": 500,
  "message": "系统异常：Cannot invoke \"Object.hashCode()\" ..."
}
```

期望结果：

未登录或 Token 缺失时应返回统一的未认证响应，例如：

```json
{
  "code": 401,
  "message": "请先登录"
}
```

影响范围：

- 影响“未登录不能访问系统内部页面”的后端稳定性。
- 前端遇到 Token 缺失或过期时，可能无法按统一逻辑跳转登录页。
- 认证异常被包装为系统异常，不利于问题定位和安全提示。

建议修复方向：

1. 在 `AuthServiceImpl.verifyToken` 或 `AuthTokenUtil.parseToken` 中先判断 Token 是否为空。
2. Token 为空时抛出明确的 `BusinessException(401, "请先登录")`。
3. 确认 `AuthInterceptor` 和 `AuthController.me` 对认证异常均返回统一格式。
4. 增加未携带 Token、空 Token、错误 Token、退出后 Token 的接口测试。

建议关注文件：

- `backend/src/main/java/com/exam/record/controller/AuthController.java`
- `backend/src/main/java/com/exam/record/service/impl/AuthServiceImpl.java`
- `backend/src/main/java/com/exam/record/util/AuthTokenUtil.java`
- `backend/src/main/java/com/exam/record/config/AuthInterceptor.java`

### 2. 前端菜单未根据角色权限动态展示

问题等级：高

复现现象：

数据库中不同角色已经配置了不同菜单权限，但前端主布局菜单为固定写死内容。

例如：

- `record_manager` 数据库权限中没有 `system:user:view`、`system:menu:view`、`system:log:view`。
- 前端侧栏仍固定渲染“系统管理”“用户管理”“菜单管理”“日志管理”。

影响范围：

- 不满足第二阶段验收标准“不同角色可以看到不同菜单”。
- 前端展示与后端权限数据不一致。
- 普通角色可能看到自己不应看到的系统管理入口。

建议修复方向：

1. 登录成功后获取当前用户可访问菜单。
2. 将菜单数据保存到前端状态或本地登录信息中。
3. `MainLayout.vue` 根据后端返回的菜单树动态渲染侧栏。
4. 路由跳转时结合菜单权限或权限标识做前端访问控制。
5. 后端也需要继续保留统一权限校验，前端只作为展示控制。

建议关注文件：

- `frontend/src/layout/MainLayout.vue`
- `frontend/src/router/index.ts`
- `frontend/src/api/auth.ts`
- `frontend/src/api/menu.ts`
- `frontend/src/utils/authToken.ts`
- `backend/src/main/java/com/exam/record/service/impl/AuthServiceImpl.java`

补充说明：

当前 `/api/auth/me` 返回的 `TokenUserVO` 只包含 `id`、`username`、`realName`，不包含角色和菜单信息。若计划由该接口驱动前端菜单，需要扩展返回结构；也可以新增“当前用户菜单树”接口。

## 四、回归验证建议

整改完成后，建议至少覆盖以下用例：

1. 未登录访问 `/dashboard`，前端应跳转到 `/login`。
2. 未携带 Token 请求 `/api/auth/me`，后端应返回 `401`。
3. 错误 Token 请求任意内部接口，后端应返回 `401`。
4. `admin` 登录后可看到系统管理菜单。
5. `record_manager` 登录后不应看到系统管理菜单。
6. `auditor` 登录后只应看到审核相关菜单。
7. 用户管理新增、编辑、禁用、启用、重置密码后，操作日志可查询到对应记录。
8. 登录成功和登录失败后，登录日志可查询到对应记录。
9. 角色分配菜单后，重新登录用户应看到最新菜单权限。
10. 算法服务不携带 `X-Internal-Api-Key` 返回 `401`，携带正确密钥返回正常结果。
