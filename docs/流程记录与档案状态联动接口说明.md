# 流程记录与档案状态联动接口说明

## 一、功能说明

本文档对应第四阶段 4.6「实现流程记录查询和档案状态联动处理」任务。

- 统一流程记录查询接口从 `audit_record` 表读取免考、课程顶替、考籍转入转出、毕业申请等业务流程记录。
- 档案状态联动由后端统一服务处理，业务审核通过后按规则更新 `student_record.record_status`，并同步写入 `record_status_log` 和 `record_change_log`。
- 已接入联动的业务：考籍转出申请审核通过后，档案状态更新为 `TRANSFERRED_OUT`。
- 后续毕业申请审核通过时，可复用同一联动服务将档案状态更新为 `GRADUATED`。

## 二、统一流程记录查询接口

### 1. 查询流程记录

- 请求方式：`GET`
- 请求地址：`/api/workflow-records`
- 权限说明：需要登录后访问。

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| businessType | String | 否 | 业务类型：`EXEMPTION`、`COURSE_REPLACE`、`TRANSFER_IN`、`TRANSFER_OUT`、`GRADUATION`。 |
| businessId | Long | 否 | 业务 ID，一般与通用申请 ID 一致。 |
| applicationId | Long | 否 | 通用申请 ID，对应 `business_application.id`。 |
| recordId | Long | 否 | 考籍档案 ID，用于查询某个档案下的全部流程轨迹。 |

> 至少需要传入一个过滤条件，否则返回参数错误。

#### 响应示例

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "id": 1,
      "applicationId": 10,
      "businessType": "TRANSFER_OUT",

      "recordId": 3,

      "beforeStatus": "SUBMITTED",

  ]
}
```

## 三、档案状态联动规则

| 业务类型 | 触发动作 | 申请状态 | 联动档案状态 | 说明 |
| --- | --- | --- | --- | --- |
| `TRANSFER_OUT` | 审核通过 | `APPROVED` | `TRANSFERRED_OUT` | 考籍转出完成后，档案不可再按正常在籍处理。 |
| `GRADUATION` | 审核通过 | `APPROVED` | `GRADUATED` | 毕业申请模块实现后复用同一联动入口。 |

## 四、联动落库说明

档案状态发生变化时，系统会同步写入以下数据：

| 表名 | 写入内容 |
| --- | --- |
| `student_record` | 更新 `record_status` 为目标状态。 |
| `record_status_log` | 记录变更前状态、变更后状态、变更原因、操作人和操作时间。 |
| `record_change_log` | 记录字段 `recordStatus` 的变更轨迹，便于档案详情页追溯。 |

如果目标状态与当前状态一致，系统不会重复写入状态日志和变更记录。
