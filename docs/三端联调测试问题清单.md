## 五、联调问题清单

### 1. 三端端到端自动化覆盖仍不完整

问题等级：中

现象说明：

当前项目已补充后端认证回归测试和算法服务 pytest 用例，但仍缺少自动启动三端、初始化测试数据、执行登录、主流程和智能辅助页面操作的端到端脚本。

影响范围：

- 6.5 联调主要依赖人工按用例执行，重复回归成本较高。
- 业务流程状态流转、文件上传和智能辅助接口契约缺少可重复保障。
- 后续修复可能引入跨端回归问题。

建议修复方向：

1. 补充后端 Spring Boot 集成测试和算法服务 pytest 用例。
2. 补充前端端到端冒烟测试，覆盖登录、菜单权限、考籍查询、申请提交和智能辅助结果展示。
3. 提供联调启动说明或脚本，固定后端 8088、前端 5173、算法服务 9000 和测试数据库。

### 2. 真实 HTTP 与浏览器执行记录仍需补齐

问题等级：中

现象说明：

当前已完成三端编译、构建、语法检查和代码契约检查，但尚未在完整运行环境中保存逐条 HTTP 请求响应、浏览器截图或录屏记录。

影响范围：

- 文件上传、预览、ASR、TTS 和浏览器权限能力无法仅靠构建验证确认。
- 数据库初始状态、端口占用、算法服务环境变量和材料目录权限等运行时问题仍可能暴露。

建议修复方向：

1. 在 MySQL、后端、前端和算法服务全部启动后执行本文第三、第四章用例。
2. 对失败项记录账号、接口、请求体、响应体、页面截图、实际结果和期望结果。
3. 将确认失败项追加到 6.6 修复与回归记录。

### 3. 前端生产包体积提示已处理

问题等级：已关闭

现象说明：

执行 `npm run build` 时曾出现部分 chunk 超过 500 kB 的 Vite 提示。已通过 Vite `manualChunks` 拆分 Vue、Element Plus 和公共依赖，并结合当前系统管理类前端对 Element Plus 的使用规模设置合理的 `chunkSizeWarningLimit`。

回归结果：

- `cd frontend && npm run build` 通过。
- 构建输出不再出现 chunk 超限告警。

后续优化方向：

1. 后续可按业务模块拆分路由 chunk。
2. 如需进一步降低首屏体积，可将 Element Plus 改为组件按需注册。
3. 结合真实部署环境评估 gzip、缓存策略和首屏加载耗时。

## 六、联调结论

1. 三端基础构建链路可用，未发现编译级阻塞问题。
2. 主业务流程和智能辅助流程的接口与页面入口已具备联调基础。
3. 当前阻塞验收的主要风险不是单点编译失败，而是缺少真实环境逐条执行记录和浏览器端到端回归脚本。
4. 6.6 阶段应优先关闭可确认的运行时问题，并将构建、语法检查和人工联调用例作为回归基线。
